[10:15] Reset: I'm not happy with the codebase. Asking for a refactor.
────────────────────────────────────────────────────────────────────────────────
After clicking through the running app for ~30 minutes, I had a list of code
smells:

  1. AppContext mixes mutable state + static seed re-exports (caused the bug).
  2. canView too lenient on 'leadership' (every employee can see leadership-only
     announcements — that's wrong).
  3. Module-level `leaderboard` is static; sending kudos doesn't move ranks.
  4. Each page has its own `if (!currentUser) return null` boilerplate.
  5. Every page has its own `<select>` markup with the same Tailwind classes.
  6. Badge uses loose Record<string,string> for colors — no autocomplete.
  7. State doesn't persist across refreshes, so demoing the moderation flow
     resets the queue every time.
  8. The /admin route accepts non-HR users — they get a "no access" message
     instead of being redirected.
  9. Page headers are duplicated inline 10+ times.
 10. `nav` arrays defined inline in three different layout files.

> Refactor the entire codebase with Claude Opus 4.7. Goals:
>   - Split selectors out of AppContext (canView, filterByTenant, leaderboard).
>   - Use a typed BadgeTone instead of color: Record<string,string>.
>   - Add useLocalStorage and useCurrentUser hooks.
>   - Persist recognitions/announcements/moderation in localStorage.
>   - Compute leaderboard dynamically from recognitions (bonus per kudos +
>     reaction).
>   - Tighten canView: 'leadership' must check visibilityPools.
>   - Role-aware ProtectedRoute (roles=['hr','admin']).
>   - Extract <PageHeader>, <FilterPills>, <Select>, <IconBadge> primitives.
>   - Move nav arrays into src/config/nav.ts.
> Don't break the existing routes or seed data. Keep all features.

This turned into the biggest single AI response of the assessment — Opus
rewrote ~25 files in one pass. I'll skip pasting the full output and just
record what landed:

  New files:
    src/hooks/useLocalStorage.ts
    src/hooks/useCurrentUser.ts        (throws if called outside ProtectedRoute)
    src/lib/selectors.ts               (canView, filterByTenant,
                                        visibleColleagues, visibleAnnouncements,
                                        computeLeaderboard)
    src/components/ui/Select.tsx
    src/components/shared/PageHeader.tsx
    src/components/shared/FilterPills.tsx
    src/components/shared/IconBadge.tsx
    src/config/nav.ts

  Rewritten:
    AppContext (no more seed re-exports; per-slice useLocalStorage; resetDemo).
    Badge (BadgeTone union, kept `color` as deprecated alias for compat).
    Button (added `subtle` variant, focus-visible rings, default type="button").
    All 10 web pages, 5 mobile pages, 4 admin pages.
    All 3 layouts (consume webNav/adminNav/mobileNav from config/nav.ts).

  Behavior changes I asked for and verified:
    - Sending kudos in /app/recognition now actually moves the user up the
      leaderboard immediately (kudos bonus +25, reaction bonus +2).
    - Logging in as alex.rivera and trying /admin redirects to /app.
    - Refreshing keeps your recognitions/published announcements.
    - Draft announcement 'ann-5' (leadership-only) is no longer visible to
      regular employees in the announcements feed — only HR/admin/CEO.

LESSONS / WHAT I'D DO DIFFERENTLY
================================================================================
- Run the app in the browser at the end of Day 1, not just `npm run dev`.
  The two import bugs would have surfaced 12 hours earlier.
- Don't let `AppContext` re-export static seed data. It always ends in tears.
- Ask for a "review pass" prompt EARLIER — by Day 2 morning. The refactor I
  asked Opus to do at 10:15 on Day 2 should probably have happened the night
  before, while the codebase was smaller.
- Capacitor + Windows: set ANDROID_HOME once at the OS level, not in the
  current shell. Saved me re-doing it after a reboot.
